# Infrastructure Tycoon

A PC-first Unity 2D management simulation about growing a single-PC hosting business into a cloud infrastructure provider.

## Development

Use **Unity 6.6 / 6000.6.9f1** (revision `8c45277fb9c5`), matching `ProjectSettings/ProjectVersion.txt`. This project deliberately uses the installed supported release rather than LTS.

Add this repository root in Unity Hub and open it with that editor. Allow Package Manager and asset import to finish. Commit Assets (including `.meta` files), Packages manifests and lockfile, and ProjectSettings; generated editor folders are ignored.

The foundation uses the built-in renderer, 2D editor defaults, Sprite tooling, uGUI, and Unity Test Framework. Open `Assets/Scenes/Main.unity` and enter Play Mode. The simulation starts on January 1, 1995 at 1x (two real seconds per day). Click PAUSE or 1x/2x/4x/8x to change the rate; the highlighted button and speed label show the selection. Pause preserves fractional-day progress, and selecting a running speed resumes the same session. Cash and alerts remain placeholders for Phase 2. Run the Edit Mode clock/catalog tests and Play Mode scene suite from Window > General > Test Runner. The same suite can run in a standalone Windows test player to verify real window resizing at 1280x720, 800x600, and 1920x1080; screenshots are saved under Application.temporaryCachePath.

The prototype garage uses reusable Garage, Player, and PCStation prefabs under Assets/Prefabs. Walk with WASD or arrow keys; diagonal movement is normalized and physics blockers stop the player at walls and the desk. Simulation pause leaves walking active. PCStation/Reach is a separate adjustable trigger from PCStation/Blocker; station-panel interaction arrives in P2-06. The camera fits the garage below the top HUD and above the status bar as the window resizes. World visuals are labeled prototype art, not a finished art pass.

Starter content is authored in `Assets/Data/StarterCatalog.asset`, referencing StarterPc, PhotoSnap, and LocalWebsite assets. Create definitions through Assets > Create > Infrastructure Tycoon. Keep explicit content IDs stable when renaming or moving assets. `StarterCatalog.ToRuntime()` validates references and IDs and creates immutable, engine-independent data; resource units are cores, GB, GB, and Mbps. Authored prices use whole dollars and convert to decimal runtime money. GameRoot references this catalog and creates an independent CompanySession with $150 cash, zero operating profit, one starter PC, and no accepted contracts. The session owns the existing clock; hardware runtime IDs are separate from content IDs. ResourceUsage exposes capacity, used demand, and available headroom in the same four units; available headroom clamps to zero for an overused dimension while retaining actual demand. CompanySession.TryAcceptOffer takes a stable offer content ID and returns a new runtime contract; TryAssignContract takes that contract ID and a hardware runtime ID. Both return a success flag and a UI-readable rejection reason. Accepted contracts start unassigned, while hosted contracts consume capacity. AvailableOffers excludes accepted offers. Acceptance and assignment do not change finances. At each outgoing month end, CompanySession bills full authored monthly revenue for hosted contracts and the PC expense once, updating cash and cumulative operating profit. Unassigned contracts earn nothing; there is no proration. BillingHistory and LastMonthlyResult expose the outgoing period, revenue, expenses, and net profit, while each hosted contract tracks PaidMonths. TryBillMonth rejects replayed or invalid periods. Panel/finance HUD binding remains in P2-07.
